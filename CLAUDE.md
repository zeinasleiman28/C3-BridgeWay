## Design decisions
- Notebook sections "## 🤝 Persona" (`PERSONA`, Rima the outreach advisor) and "## 📋 Instructions"
  (`INSTRUCTIONS`, 10 numbered rules + one worked example). app.py holds identical copies (sync test).
- Tools validate input and return `{"status": "error", "reason": ...}` or `{"status": "recorded", "id": ...}`;
  they print an emoji log line and append JSONL with an ISO timestamp. `TOOL_REGISTRY` maps names → functions;
  `run_tool(name, arguments)` never raises. Definitions are written once MCP-style and converted to `OPENAI_TOOLS`.
- `build_system_prompt(route_hint)` = PERSONA + INSTRUCTIONS + Business Summary + Business Profile (PDF) + hint.
  Defined in the notebook as a thin wrapper around `knowledge.compose_system_prompt(...)`.
- `classify_intent(message, history)` → `{"intent", "confidence", "reason"}`; LLM at temperature 0 returning
  JSON, keyword fallback; prints `[ROUTER] ...` and logs to `logs/router.jsonl`.
- Provider from `.env`: `LLM_PROVIDER=gemini` (gemini-2.5-flash via the OpenAI-compatible endpoint) or
  `openai` (gpt-4o-mini); `LLM_MODEL` overrides.
- `chat(message, history)`: route → build messages (history capped ~20 turns) → tool loop (max 5) →
  reflection (`USE_REFLECTION`) → reply. Friendly error messages instead of crashes.
